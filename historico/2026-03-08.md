## ⚠️ SESSÃO 08/03/2026 (TARDE) — PROBLEMA BINANCE API — PENDENTE

### Problema
Integração Binance via API Key não funciona em produção.
Binance bloqueia TODOS os IPs de cloud compartilhados (Vercel, AWS serverless, GCP, Cloudflare).
Todas as regiões Vercel tentadas foram bloqueadas: gru1, fra1, dub1 (Edge também).

### Solução criada (falta só o deploy)
**Railway proxy server** — servidor Node.js dedicado com IPs não bloqueados pela Binance.

### Arquivos já prontos
- `binance-proxy-server/server.js` — servidor proxy (sem dependências NPM)
- `binance-proxy-server/package.json`
- `binance-proxy-server/railway.json`
- `src/lib/exchanges/binance-browser.ts` — já lê `NEXT_PUBLIC_BINANCE_PROXY_URL`

### PASSO A PASSO PARA AMANHÃ

**1. Deploy Railway (na pasta do proxy):**
```bash
cd ~/Desktop/Projetos\ AI/meu-imposto-cripto/binance-proxy-server
railway init
# → escolher "Empty Project", dar nome "binance-proxy"
railway up --detach
```

**2. Definir região EU West no Railway (CRÍTICO)**
- Dashboard Railway → Settings → Region → **EU West**
- US também é bloqueado pela Binance

**3. Pegar a URL pública:**
```bash
railway status
```
Formato: `https://binance-proxy-xxxx.up.railway.app`

**4. Adicionar variável no Vercel**
- vercel.com → meu-imposto-cripto → Settings → Environment Variables
- `NEXT_PUBLIC_BINANCE_PROXY_URL` = `https://[URL-DO-RAILWAY]`

**5. Atualizar CSP no `next.config.ts`**
- Na linha `connect-src`, adicionar a URL do Railway ao final

**6. Redeploy Vercel:**
```bash
cd ~/Desktop/Projetos\ AI/meu-imposto-cripto
vercel --prod
```

**7. Testar:** abrir o app → Exchanges → conectar Binance → Sincronizar

### Por que Railway vai funcionar
- Vercel usa IP range compartilhado que a Binance bloqueou em bloco
- Railway US West / EU West usam IPs de datacenter não listados no blocklist da Binance
- O apiSecret NUNCA vai para o Railway — browser já calcula HMAC-SHA256 localmente
- CoinTracking (referência do mercado) usa o mesmo modelo: servidor dedicado em AWS eu-west-1
