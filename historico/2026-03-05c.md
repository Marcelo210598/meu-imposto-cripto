# Snapshot - 2026-03-05c (Sessão 3 — Stripe Live em Produção)

## O que foi feito hoje
- Diagnosticado erro "Erro de conexão. Tente novamente." no checkout
- Identificado: rota `/api/stripe/checkout` não tinha try/catch — retornava 500 HTML em vez de JSON
- Adicionado try/catch em `/api/stripe/checkout` e `/api/stripe/portal` com mensagens de erro legíveis
- Diagnosticado que TODAS as env vars Stripe na Vercel tinham `\n` literal no final
  - Causa: forma como foram configuradas no Vercel incluiu trailing newline
  - O Stripe recebia `price_xxx\n` e `sk_live_xxx\n` → connection error
- Corrigidas 5 env vars via `echo -n` + `vercel env add --force`:
  - STRIPE_SECRET_KEY
  - STRIPE_WEBHOOK_SECRET
  - NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY
  - STRIPE_PRICE_PRO
  - STRIPE_PRICE_CONTADOR
- Confirmado checkout funcionando em produção (live mode, R$29/mês)

## Decisoes tecnicas
- Usar sempre `echo -n "valor"` ao configurar env vars no Vercel via CLI para evitar trailing newline
- try/catch obrigatorio em todas as chamadas Stripe — Next.js retorna HTML em 500 nao tratado

## Problemas encontrados e solucoes
- Problema: "Erro de conexao. Tente novamente." no checkout
- Solucao 1: try/catch na rota para retornar JSON de erro sempre
- Solucao 2: strip do `\n` nas env vars (diagnosticado via `cat -v` no arquivo .env puxado do Vercel)
